# Iterative Sorting: Merge Sort & Quick Sort

## Постановка задачи

Реализовать **итеративные** (без использования рекурсии и системного стека вызовов) версии двух алгоритмов сортировки:

1. **Merge Sort (сортировка слиянием)** — с использованием циклов (снизу вверх, bottom-up).
2. **Quick Sort (быстрая сортировка)** — с использованием явного стека итераций.

---

## 1. Объяснение решения

### 1.1. Итеративный Merge Sort (Bottom-Up)

Рекурсивный Merge Sort работает сверху вниз (разделяй и властвуй). Итеративная версия переворачивает этот процесс снизу вверх:

1. Мы рассматриваем исходный массив как набор подмассивов («бегов») длиной `width = 1`.
2. В цикле проходим по массиву и сливаем соседние пары блоков длиной `width` в отсортированные блоки длиной `2 * width`.
3. На каждой итерации внешнего цикла удваиваем `width` (`1`, `2`, `4`, `8` и т.д.), пока `width` не станет больше или равен длине массива `n`.
4. Для реализации без выделения памяти на каждом шаге используется вспомогательный буфер (`buf`), а указатели `result` и `buf` меняются местами после каждого уровня слияния.

### 1.2. Итеративный Quick Sort (с явным стеком)

Рекурсию в Quick Sort можно заменить хранением границ обрабатываемых подмассивов в явной структуре данных — стеке (`list` в Python):

1. Помещаем в стек начальные границы всего массива: `stack = [(0, n - 1)]`.
2. В цикле `while stack:` извлекаем текущие границы `lo` и `hi`.
3. Выполняем стандартное разбиение (partition), получая позиции для дальнейшей обработки.
4. Чтобы гарантировать ограничение памяти на стек в худшем случае до $O(\log n)$, **меньший подмассив всегда помещается в стек последним** (чтобы обрабатываться в первую очередь).

## 2. Оценка сложности

| Алгоритм | Время (среднее / худшее) | Память | Описание по памяти |
| --- | --- | --- | --- |
| **Merge Sort Iterative** | $O(n \log n)$ / $O(n \log n)$ | **O(n)** | Требуется вспомогательный буфер размером с массив для слияния. |
| **Quick Sort Iterative** | $O(n \log n)$ / $O(n^2)$ | **O(\log n)** | Память под явный стек индексов в среднем (в худшем случае $O(n)$ при плохом выборе pivot). |

## 3. Визуализация работы алгоритмов (на примере `[5, 2, 9, 1]`)

### Итеративный Merge Sort (`width` растет снизу вверх)

* Исходный массив: `[5, 2, 9, 1]`, `n = 4`
* **Шаг 1 (`width = 1`):** Сливаем блоки по 1 элементу.
* Сливаем `[5]` и загоняем с `[2]` $\rightarrow$ `[2, 5]`
* Сливаем `[9]` и загоняем с `[1]` $\rightarrow$ `[1, 9]`
* Промежуточный результат: `[2, 5, 1, 9]`


* **Шаг 2 (`width = 2`):** Сливаем блоки по 2 элемента.
* Сливаем `[2, 5]` и `[1, 9]` $\rightarrow$ `[1, 2, 5, 9]`


* **Итог:** `[1, 2, 5, 9]` ✔

## 4. Тесты (`test_iter.py`)

Набор тестов покрывает все критические сценарии:

* **Базовые и граничные:** пустой массив `[]`, один элемент `[1]`, два элемента.
* **Особые случаи:** уже отсортированный массив, обратный порядок, отрицательные числа, массивы с большим количеством дубликатов.
* **Контракт безопасности:** проверка того, что исходный массив не мутирует (функции возвращают новый отсортированный список).
* **Сравнение на больших данных ($n = 5000$):** проверка производительности на случайных, отсортированных и полностью идентичных данных (`all_equal`).
