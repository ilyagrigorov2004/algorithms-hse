# K-th largest element — Quickselect

## Постановка

Даны `nums` и `k`. Найти k-й по величине элемент (1-индексированный).
Нельзя сортировать и использовать кучи.

| Вход | Выход |
|---|---|
| `[3,2,1,5,6,4]`, `k=2` | `5` |
| `[3,2,3,1,2,4,5,5,6]`, `k=4` | `4` |

## Идея

Quickselect — «половинчатый» quicksort. Переводим `k`-й по величине в
индекс по возрастанию: `target = n − k`. Выбираем pivot (середина
диапазона), делаем разделение Хоара. После него `a[lo..j] ≤ pivot ≤ a[i..hi]`.

- `target ≤ j` → ищем слева;
- `target ≥ i` → ищем справа;
- `j < target < i` → ответ на месте: `a[target] == pivot`.

Третья ветка критична: без неё на массиве из одинаковых элементов
получаем O(n²), с ней — O(n) за один проход. Реализация итеративная
(без рекурсии), вход копируется, `k` вне `[1,n]` → `ValueError`.

## Сложность

| | Средний | Худший |
|---|---|---|
| Время | **O(n)** | O(n²) |
| Память | O(n) | O(n) |

O(n) в среднем: n + n/2 + n/4 + … = 2n. O(n²) — если pivot каждый
раз отрезает 1 элемент. Память O(n) — на копию входа.

## Визуализация

`nums = [3,2,1,5,6,4]`, `k=2`, `target=4`.

| Шаг | `lo..hi` | `pivot` | После разделения | Решение |
|---|---|---|---|---|
| 1 | 0..5 | 1 | `a=[1,2,3,5,6,4]`, `j=0, i=2` | `target ≥ i` → `lo=2` |
| 2 | 2..5 | 5 | `a=[1,2,3,4,6,5]`, `j=3, i=4` | `target ≥ i` → `lo=4` |
| 3 | 4..5 | 6 | `a=[1,2,3,4,5,6]`, `j=4, i=5` | `target ≤ j` → `hi=4` |
| 4 | 4..4 | — | — | `a[4] = 5` ✔ |

## Тесты

`test_quickselect.py`, 25 тестов:

- **Примеры из задания** — оба кейса.
- **Граничные** — 1 элемент, 2 элемента, `k=1`, `k=n`, sorted /
  reverse-sorted, отрицательные.
- **Дубликаты** — all-equal, группы повторов, перебор всех `k` с
  проверкой против `sorted()`.
- **Контракт** — вход не мутируется; `k` вне `[1,n]` → исключение.
- **Случайные против `sorted()`** — 200 малых, 30 больших, 100 с
  малым числом разных значений.
- **Нетривиальные** — медианы, палиндром, чередование экстремумов.
- **Бенчмарки**:
  - `all_equal_large`: `[7]*50_000` < 2 с (регресс на O(n²));
  - `vs_python_sort`: O(n) быстрее Python-сортировки на n=50_000
    (сравнение с C-`sorted()` некорректно — константы C в 10–50×
    лучше);
  - `linear_scaling`: `t(2n)/t(n) ≈ 2`, а не `≈ 4`.

Запуск: `pytest homework_6/kth/ -v` → **25 passed**.
