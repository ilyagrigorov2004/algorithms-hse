# Compare: Merge Sort vs Quick Sort
## 1. Объяснение решения

### Merge Sort

Стратегия «разделяй и властвуй»:

1. **База:** массив длины 0 или 1 уже отсортирован.
2. **Разделение:** делим массив пополам (`mid = len // 2`).
3. **Рекурсия:** сортируем каждую половину независимо.
4. **Слияние:** сливаем два отсортированных массива в один проход
   двумя указателями — на каждом шаге берём меньший из двух головных
   элементов и продвигаем указатель.

Ключевое свойство — **инвариантность к входным данным**: длина массива
определяет глубину рекурсии, а не значения элементов. Поэтому
отсортированный, обратный и случайный массивы обрабатываются одинаково.

### Quick Sort (pivot = `arr[0]`)

1. **База:** массив длины ≤ 1 уже отсортирован.
2. **Pivot:** берём первый элемент `arr[0]`.
3. **Разбиение:** раскладываем элементы в три списка — `left` (`< pivot`),
   `middle` (`== pivot`), `right` (`> pivot`). Отдельный `middle` решает
   проблему дубликатов — они не попадают в рекурсию.
4. **Рекурсия:** сортируем `left` и `right`, склеиваем `left + middle + right`.

Проблема **именно этого** pivot: если массив уже отсортирован, `arr[0]` —
минимум, `left` пустой, `right` содержит `n-1` элемент. Рекурсия уходит
на глубину `n`, а на каждом уровне делается O(n) работы → **O(n²)**.

### Quick Sort (pivot = середина)

То же самое, но pivot — `arr[len(arr) // 2]`. На отсортированном массиве
это **медиана**, идеально делящая его пополам → глубина рекурсии
log₂(n), сложность **O(n log n)**.

### Декоратор `timer`

Навешан на **публичную обёртку**, а рекурсия идёт через внутреннюю
`_merge_sort` / `_quick_sort` / `_quick_sort_mid`. Если декоратор
повесить прямо на рекурсивную функцию, каждый вызов печатает строку →
лог раздувается до тысяч строк. С обёрткой на весь вызов печатается
ровно одна строка — лог читаемый.

## 2. Оценка сложности

Обозначим `n` — длина массива.

| Алгоритм | Время (сред.) | Время (худш.) | Память |
|---|---|---|---|
| Merge Sort | O(n log n) | O(n log n) | **O(n)** |
| Quick Sort (`pivot = arr[0]`), случайные данные | O(n log n) | — | O(log n) |
| Quick Sort (`pivot = arr[0]`), отсортированные / обратные | — | **O(n²)** | **O(n)** |
| Quick Sort (`pivot = середина`), любые данные | O(n log n) | O(n log n) (для отсортир.) | O(log n) |

### Откуда берутся оценки

**Merge Sort.**
- Время: рекуррентность `T(n) = 2·T(n/2) + O(n)` (слияние — линейное).
  По мастер-теореме (a=2, b=2, f(n)=O(n)) получаем `T(n) = O(n log n)`.
- Память: на каждом уровне рекурсии создаются новые списки `left_half`,
  `right_half`, `result`. Суммарно по всем уровням — `O(n)` в каждый
  момент времени (в глубину хранится не более одного уровня одновременно).
  Плюс глубина рекурсии `O(log n)`. Итого **O(n)**.

**Quick Sort с `pivot = arr[0]`.**
- **Средний случай** (случайные данные): pivot делит массив примерно
  пополам с высокой вероятностью → `T(n) ≈ 2·T(n/2) + O(n)` = **O(n log n)**.
- **Худший случай** (отсортированный / обратный массив): pivot — минимум
  (или максимум), `left` (или `right`) пустой → `T(n) = T(n-1) + O(n)`,
  разворачивается в `O(n) + O(n-1) + ... + O(1) = O(n²)`.
- **Память:** в среднем стек рекурсии глубины `O(log n)` + суммарно
  `O(n)` на списки `left/middle/right` по всем активным уровням.
  В худшем случае стек глубины `O(n)`, плюс те же `O(n)` на списки.
  Итого **O(n)**.

**Quick Sort с `pivot = середина`.**
- На отсортированном массиве средний элемент = медиана → деление
  строго пополам → **O(n log n)**, стек `O(log n)`.
- На случайных данных — то же среднее O(n log n).
- **Худший случай всё ещё возможен** (например, специально подобранный
  массив, где средний по индексу элемент — крайний по значению), но
  на практике вероятность пренебрежимо мала. Защититься полностью
  можно случайным выбором pivot, но это выходит за рамки задания.

## 3. Визуализация работы алгоритмов

Возьмём массив `arr = [5, 2, 9, 1, 5, 6]`, `n = 6`.

### Merge Sort: пошагово

**Уровень деления (сверху вниз):**

```
                    [5, 2, 9, 1, 5, 6]
                    /                \
              [5, 2, 9]            [1, 5, 6]
              /       \            /       \
           [5]      [2, 9]       [1]      [5, 6]
                    /    \                /     \
                  [2]    [9]            [5]     [6]
```

**Уровень слияния (снизу вверх):**

| Шаг | Сливаем | Результат |
|---|---|---|
| 1 | `[2]` + `[9]` | `[2, 9]` |
| 2 | `[5]` + `[2, 9]` | `[2, 5, 9]` |
| 3 | `[5]` + `[6]` | `[5, 6]` |
| 4 | `[1]` + `[5, 6]` | `[1, 5, 6]` |
| 5 | `[2, 5, 9]` + `[1, 5, 6]` | **`[1, 2, 5, 5, 6, 9]`** |

Пошагово для шага 5 (два указателя):

```
left  = [2, 5, 9]      i=0
right = [1, 5, 6]      j=0
result = []

i=0,j=0: left[0]=2 vs right[0]=1  → берём 1,  result=[1],       j=1
i=0,j=1: left[0]=2 vs right[1]=5  → берём 2,  result=[1,2],     i=1
i=1,j=1: left[1]=5 vs right[1]=5  → берём 5 (<=), result=[1,2,5],   i=2
i=2,j=1: left[2]=9 vs right[1]=5  → берём 5,  result=[1,2,5,5], j=2
i=2,j=2: left[2]=9 vs right[2]=6  → берём 6,  result=[1,2,5,5,6], j=3
right кончился → extend left[2:] = [9]
result = [1, 2, 5, 5, 6, 9]
```

### Quick Sort (pivot = `arr[0]`): пошагово

`arr = [5, 2, 9, 1, 5, 6]`, pivot = 5.

**Разбиение 1:**

```
pivot = 5
left   = [2, 1]           (элементы < 5)
middle = [5, 5]           (элементы == 5)
right  = [9, 6]           (элементы > 5)

→ рекурсивно сортируем left=[2,1] и right=[9,6]
```

**Разбиение 2 (для `[2, 1]`, pivot = 2):**

```
pivot = 2
left   = [1]
middle = [2]
right  = []
→ [1] + [2] + [] = [1, 2]
```

**Разбиение 3 (для `[9, 6]`, pivot = 9):**

```
pivot = 9
left   = [6]
middle = [9]
right  = []
→ [6] + [9] + [] = [6, 9]
```

**Сборка:**

```
[1, 2] + [5, 5] + [6, 9] = [1, 2, 5, 5, 6, 9]  ✅
```

На этом примере pivot = 5 удачно делит массив → логарифмическая глубина.
На **отсортированном** `[1, 2, 3, 4, 5, 6]` было бы:

```
pivot = 1
left   = []
middle = [1]
right  = [2, 3, 4, 5, 6]     ← рекурсия глубины 5

pivot = 2
left   = []
middle = [2]
right  = [3, 4, 5, 6]        ← глубина 4

...и т.д. → всего n уровней × O(n) работы = O(n²)
```

### Quick Sort (pivot = середина) на отсортированном `[1..6]`

```
pivot = arr[3] = 4
left   = [1, 2, 3]
middle = [4]
right  = [5, 6]
```

Идеальное деление пополам на каждом уровне → O(n log n).

## 4. Тесты

Файл `test_sorts.py` содержит:

| Тест | Что проверяет |
|---|---|
| `test_merge_sort_basic` | Корректность Merge Sort на `[5,2,9,1,5,6]` |
| `test_quick_sort_basic` | Корректность Quick Sort с `arr[0]` |
| `test_quick_sort_mid_basic` | Корректность Quick Sort с серединой |
| `test_empty_and_single` | **Граничные случаи:** `[]` и `[1]` для всех трёх |
| `test_already_sorted` | Отсортированный вход |
| `test_reverse_sorted` | Обратный порядок |
| `test_random_matches_sorted` | 20 случайных массивов, все три = `sorted()` |
| `test_huge_random_array` | n=1000, случайные данные — все ~ O(n log n) |
| `test_huge_sorted_array` | n=1000, отсортирован — демонстрация O(n²) у `arr[0]` |
| `test_huge_reverse_sorted_array` | n=1000, обратный порядок — тоже O(n²) у `arr[0]` |

Для больших тестов используется `sys.setrecursionlimit(10_000)` —
иначе Quick Sort с `pivot = arr[0]` на n=1000 упадёт с `RecursionError`
раньше, чем мы успеем замерить время.

## 5. Результаты замеров

Запуск `python -m pytest test_sorts.py -s` на машине разработчика:

```
--- Случайный массив (1000 эл.) ---
  Merge Sort                 2.60 мс
  Quick Sort (arr[0])        1.40 мс
  Quick Sort (mid)           1.06 мс

--- Отсортированный массив (1000 эл.) ---
  Merge Sort                 2.20 мс
  Quick Sort (arr[0])       74.55 мс        ← вырождение в O(n²)
  Quick Sort (mid)           2.98 мс
  Quick(arr[0]) медленнее Merge в 33.8× раз

--- Обратный порядок (1000 эл.) ---
  Merge Sort                35.25 мс        ← «холодный» запуск
  Quick Sort (arr[0])       41.33 мс
  Quick Sort (mid)           1.00 мс
```

**Выводы:**

1. На **случайных** данных все три алгоритма работают сравнимо — O(n log n).
2. На **отсортированном** массиве Quick Sort с `pivot = arr[0]` работает
   в **33.8 раза медленнее** Merge Sort. Это эмпирическое подтверждение
   вырождения O(n log n) → O(n²).
3. Выбор **среднего элемента** в качестве pivot полностью убирает
   вырождение: Quick Sort (mid) работает на уровне Merge Sort и на
   случайных, и на отсортированных данных.
4. Merge Sort инвариантен к порядку данных — его время определяется
   только `n`. Разброс 2.2 мс vs 35.25 мс на последнем тесте — это
   «холодный» интерпретатор (первый запуск в сессии), а не свойство
   алгоритма.
