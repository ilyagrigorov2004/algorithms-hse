# Validate BST (Проверка бинарного дерева поиска)

## 1. Объяснение решения

Задача требует проверить, является ли произвольное бинарное дерево корректным бинарным деревом поиска (BST).

**Свойство BST:** для каждого узла все значения в его левом поддереве строго меньше значения узла, а все значения в правом поддереве строго больше. Дубликаты не допускаются.

**Идея алгоритма:**
В корректном BST обход **In-order (LNR — Лево, Узел, Право)** всегда даёт **строго возрастающую** последовательность чисел. Это связано с тем, что мы сначала обходим все меньшие элементы (левое поддерево), затем сам узел, а затем все большие элементы (правое поддерево).

**Как связана идея с реализацией:**
1. Мы запускаем рекурсивный In-order обход, который собирает значения всех узлов в список `answer`.
2. После обхода мы проходим по списку и проверяем, что каждое следующее число строго больше предыдущего (`answer[i] >= answer[i+1]`).
3. Если находим нарушение порядка или дубликат, возвращаем `False`.
4. Если список полностью отсортирован по возрастанию, возвращаем `True`.

Проверять только левого и правого ребенка недостаточно, так как ошибка может быть глубоко в поддереве (например, значение в правом поддереве может быть меньше корня).

## 2. Оценка сложности

| Параметр | Оценка | Объяснение |
|----------|--------|------------|
| **Время** | `O(n)` | In-order обход посещает каждый узел ровно один раз (`n` — число узлов). Проход по списку для проверки сортировки также занимает `O(n)`. Итого `O(n) + O(n) = O(n)`. |
| **Память** | `O(n)` | Список `answer` хранит значения всех узлов `O(n)`. Стек рекурсии в худшем случае (вырожденное дерево) занимает `O(h)`, где `h` — высота, то есть `O(n)`. Итого `O(n)`. |

## 3. Визуализация работы алгоритма

### Пример 1: Корректный BST (результат True)

Дерево:
```text
       8
      / \
     3   10
    / \
   1   6
```

**Пошаговый In-order обход (Лево → Узел → Право):**

| Шаг | Узел | Действие | Список `answer` |
|-----|------|----------|-----------------|
| 1 | 1 | Дошли до левого листа | `[1]` |
| 2 | 3 | Вернулись в родителя | `[1, 3]` |
| 3 | 6 | Пошли в правое поддерево узла 3 | `[1, 3, 6]` |
| 4 | 8 | Вернулись в корень | `[1, 3, 6, 8]` |
| 5 | 10 | Пошли в правое поддерево корня | `[1, 3, 6, 8, 10]` |

**Проверка:** `[1, 3, 6, 8, 10]` — строго возрастает. `1 < 3 < 6 < 8 < 10`. 
**Результат:** `True` ✅

---

### Пример 2: Некорректный BST (результат False)

Дерево:
```text
       5
      / \
     1   4
        / \
       3   6
```
*Ошибка:* узел 4 находится в правом поддереве 5, но 4 < 5, что нарушает свойство BST.

**Пошаговый In-order обход:**

| Шаг | Узел | Действие | Список `answer` |
|-----|------|----------|-----------------|
| 1 | 1 | Левый лист корня | `[1]` |
| 2 | 5 | Корень | `[1, 5]` |
| 3 | 3 | Левый лист узла 4 | `[1, 5, 3]` |
| 4 | 4 | Узел 4 | `[1, 5, 3, 4]` |
| 5 | 6 | Правый лист узла 4 | `[1, 5, 3, 4, 6]` |

**Проверка:** 
- `1 < 5` — ок.
- `5 >= 3` — **нарушение!** (5 больше 3, но стоит перед ним).

**Результат:** `False` ❌

---

### Пример 3: Дерево с дубликатами (результат False)

Дерево:
```text
    5
   /
  5
```
**In-order обход:** `[5, 5]`
**Проверка:** `5 >= 5` — **нарушение!** Дубликаты недопустимы.
**Результат:** `False` ❌

## 4. Тесты

Полный набор тестов находится в файле `test_validate_bst.py`. Запуск: `pytest test_validate_bst.py -v`.

Тесты покрывают:
- Корректные деревья (разных размеров).
- Некорректные деревья (ошибка в корне и глубоко в поддереве).
- Пустое дерево (`True`).
- Дерево из одного узла (`True`).
- Деревья с дубликатами (`False`).
- Деревья с отрицательными числами.
- Вырожденные деревья (только левые или только правые дети).
